# Nexora Bank + OreMarket

Общий сайт банка и биржи Minecraft: вход через Discord, единая серверная база, банк, рынок и админ-панели.

## Как это устроено

GitHub хранит исходный код. Для работающего сайта нужен Node.js-сервер: приложение использует Express, Discord OAuth и SQLite. Поэтому включить только GitHub Pages недостаточно — Pages публикует статические файлы и не запускает серверные маршруты.

Готовая настройка рассчитана на Render: подключается публичный GitHub-репозиторий, запускается Node-сервис, а SQLite и загруженные картинки сохраняются на постоянном диске. SQLite рассчитан на один экземпляр сайта; диск сохраняет данные между перезапусками и публикациями.

## Публикация

1. Распакуй `Nexora-GitHub.zip` на компьютере.
2. Создай на GitHub новый публичный репозиторий.
3. Загрузи в него **содержимое** распакованной папки (файлы и папки проекта, включая `render.yaml`), затем нажми **Commit changes**. Сам ZIP внутрь репозитория загружать не нужно.
4. В Render выбери **New → Blueprint**, подключи этот репозиторий и подтверди настройки из `render.yaml`.
5. Render запросит Discord Client ID, Discord Client Secret и `ADMIN_IDS`. В `ADMIN_IDS` укажи Discord ID владельца; несколько ID разделяй запятой. Не публикуй Client Secret.
6. После первой публикации открой страницу сервиса в Render и скопируй его URL вида `https://имя-сервиса.onrender.com`.
7. В Discord Developer Portal открой приложение → **OAuth2** → **Redirects** и добавь `<URL-сайта>/auth/callback`, например `https://имя-сервиса.onrender.com/auth/callback`.
8. Открой сайт по адресу Render. Банк и OrMarket используют общий вход и одну базу.

В Render выбран план с постоянным диском `/var/data`. Диск нужен для сохранения SQLite-базы и картинок между публикациями. Пока к сервису подключён SQLite-диск, сайт работает в одном экземпляре; частые публикации могут кратко перезапускать сервис.

Для уведомлений и вызова банкира можно дополнительно задать `DISCORD_WEBHOOK_URL`, `BANKER_ROLE_ID`, `ADMIN_ROLE_ID` и `ORDERS_WEBHOOK_URL` в разделе **Environment** Render. Они не нужны для самого входа и первого запуска.

## Локальный запуск

1. Установи Node.js 22.
2. Скопируй `.env.example` в `.env`.
3. Заполни `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `ADMIN_IDS` и длинный случайный `JWT_SECRET`. В настройках Discord OAuth2 добавь `http://localhost:3000/auth/callback`.
4. В папке проекта выполни `npm install`, затем `npm start`.
5. Открой `http://localhost:3000`.

На Render адрес OAuth автоматически берётся из URL сервиса. Для локального запуска используется `BASE_URL` из `.env`.

## Что не входит в публикационный архив

- `.env` и реальные ключи Discord — их нужно задать в секретах Render.
- `data.db` — база пользователей и балансов.
- Загруженные картинки из `uploads/`.
- `node_modules/` — зависимости Render установит во время сборки.

Публичный репозиторий не должен содержать секреты или базу реальных пользователей. Новый Render-сервис создаст новую базу. Если нужно перенести действующие данные, не загружай `data.db` в публичный репозиторий — сначала сделай отдельную резервную копию и переноси её только в закрытое хранилище сервера.

## Структура

- `public/` — сайт банка, OrMarket и панели управления.
- `server.js` — сервер, Discord-вход и API.
- `admin.js`, `oremarket.js`, `apps.js`, `orders.js`, `news.js` — функции сайта.
- `render.yaml` — настройки публикации на Render.
- `.env.example` — пример настроек для локального запуска.
